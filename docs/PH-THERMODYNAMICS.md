# Offline pressure–enthalpy calculations

PhaseKit's P–h tool uses a bounded, static property grid derived from the [CoolProp 7.2.0](https://github.com/CoolProp/CoolProp/tree/v7.2.0) HEOS equations of state and predefined mixture models (MIT licence). The Python wheel reports Git revision `98b3523d5daa98454618d381d2ae53f7471d216b`. The generated grid ships with the app; calculation requires no network request, Python installation, or runtime call to CoolProp. It is a **model-derived engineering estimate**, not a measurement or a legally verified property.

Enthalpy is CoolProp `Hmass` in kJ/kg relative to that fluid model's reference state. Energy differences within a refrigerant are meaningful; absolute enthalpy numbers are not a common reference for comparing different fluids. The R729 Air curve follows CoolProp's pseudo-pure Air model. It is not a fixed chemical-mixture recipe or measured composition for a particular air sample.

`data/ph/generate.py` reads the exact canonical IDs and CoolProp fluid identities from the P–T table, then samples saturation bubble/dew states and enthalpy at fixed temperature offsets into the vapour and liquid regions. The grid does not include two-phase P,T enthalpy data. `packages/core/generated/ph-grids.json` contains the model data and a SHA-256 content prefix in its `dataVersion`; `data/ph/coverage-manifest.json` states which refrigerants are supported and why each other record is excluded. This source version supports **113 of 249** catalogue records. The method interpolates enthalpy between same-phase temperature-offset samples and adjacent log-pressure planes. It does not extrapolate beyond available pressure or temperature offsets, and never interpolates through the vapour–liquid boundary. Input temperatures within one kelvin of the saturation boundary are blocked. The pressure convention is absolute bar internally, with gauge conversion requiring an atmospheric reference.

The pressure grid is within both bubble/dew P–T domains, capped at 60 bar and ending at 88% of their common upper pressure. CoolProp must report a finite triple-point temperature; published saturation and single-phase sample temperatures are at least 3 K above it. Failed or anomalous source states split the allowed pressure domain. The model contains no solid-phase calculations, and its sampled range does not authorize use at freezing or metastable conditions. For mixtures, the reported triple point and validity of phase branches are model properties; users must apply any more restrictive material limits separately.

The cycle accepts low and high pressure, suction temperature T1, discharge temperature T2 and liquid-line temperature T3. State 1 and 2 must be superheated vapour, and state 3 must be subcooled liquid. The fourth point is an **isenthalpic expansion assumption**: h4 = h3 at low pressure. The present tool only returns a cycle if this places state 4 between the low-pressure saturated-liquid and saturated-vapour enthalpies. For this two-phase state, it reports the bubble–dew temperature bounds; vapour quality is not reported because linear interpolation between blend endpoints is not a general mixture flash model. It does not invent a single T4 for a zeotropic blend. Superheat is T1 minus low-pressure dew temperature; subcooling is high-pressure bubble temperature minus T3. Reported superheat, subcooling and point-4 bubble/dew temperature bounds use the separately validated high-density offline P–T provider; both dataset versions and source IDs are returned with the result. The sparse P–h dome supplies enthalpy geometry and is not used to claim 0.1 °C temperature accuracy. No compressor power, electrical power, cooling capacity or COP is inferred from these five measurements.

`data/ph/validate.py` independently evaluates off-grid pressures and temperature offsets against fresh CoolProp Hmass(P,T) calls. The generator clips the pressure domain to the longest contiguous run of validated cells; if too few remain, that fluid is unsupported. A cell is excluded if a withheld sample fails to evaluate or differs by more than 2 kJ/kg. The published grid passed **29,741 withheld evaluations**, with no source-evaluation failures, maximum absolute enthalpy error **1.896 kJ/kg**, and 99th-percentile absolute error **0.570 kJ/kg**. This is a bound on the tested interpolation cells against the source model, **not** a general uncertainty bound for CoolProp or a guarantee for untested points. Unsupported fluids or phase/range violations produce explicit errors; no substitute refrigerant curve is used.
