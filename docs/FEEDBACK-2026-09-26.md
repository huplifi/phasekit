## Feedback and proposed acceptance criteria

1. **Filter alignment and boolean controls.** Align labels, help icons and inputs consistently across filter rows. Replace appropriate on/off settings with the existing touch-friendly switch style. Audit all boolean controls, including leak-check options. Keep labels clickable and keyboard/focus states accessible.
2. **Picker list.** Show all matching refrigerants in the scrollable modal without a Show more gate. Preserve search, favourite-first ordering and responsive scrolling without body overflow.
3. **Picker tabs.** Remove the redundant Favourites tab; favourites remain visibly grouped first without duplicate rows.
4. **Useful conversions and spacing.** Expand field-relevant conversions rather than adding quantities for their own sake. Candidates: refrigeration power (kW, BTU/h, refrigeration tons), vacuum (Pa, mbar, Torr/microns of mercury), and length (mm/in). Verify definitions and sources before implementation. Existing pressure and flow conversions remain useful. Give notes, results and Save actions consistent spacing; do not make report creation the primary purpose of a simple conversion.
5. **Checklists.** Align the template selector and Create action. Replace default checkbox rendering with deliberate touch-friendly controls. Switches are suitable for settings; large styled completion checkboxes are a proposed alternative for completed tasks. Current checklists already update local application data automatically and can be reopened under Your checklists. Make persistence, success/failure and reopening discoverable. Add direct print/PDF output for a completed or partially completed checklist, clearly preserving its status and entered observations.
6. **Saved records and field documentation.** Give collapsed records meaningful summaries, for example `Power · 1000 W → 1 kW`, with date and equipment when available. Use the selected interface language rather than a bilingual generic title. Provide direct printing for meaningful assessments/results without a mandatory save-and-navigate detour. Preserve input values, units, source/version information and notes. A concise image export/share card for phones is an exploratory follow-up, not yet a firm requirement. Do not remove useful reporting merely because one conversion is trivial.
7. **Volume and flow.** Keep the existing bounded geometry calculations; the owner has not yet studied these topics and did not request their removal. Keep explanations clear and do not imply pipe sizing or pressure-loss capability.
8. **Pipe thermal expansion.** Proposed addition within the pipe tool: material, reference length, initial temperature and final temperature; signed length change and final length. Use source-backed coefficients with applicability limits and make free, uniform expansion assumptions explicit. Preserve contraction as a negative change. Do not imply support, stress or expansion-loop design.
9. **Icons.** The application uses `lucide-react`. The CO₂e calculator heading already uses an SVG `ArrowLeftRight`, but shared text labels still include the Unicode arrow. Audit every visible occurrence and verify on iPhone rather than assuming a cache issue. Use SVG icons consistently. Give comparison and general conversion distinct icons; currently both use `ArrowLeftRight` in tool navigation.
10. **Regression prevention.** Treat the reported alignment, spacing and inconsistent controls as defects. Automated checks alone did not establish visual consistency. Reuse established controls and inspect affected routes in light/dark themes, FI/EN and mobile/desktop layouts, including keyboard/touch interaction. Record actual visual evidence and any unverified physical-device behaviour.
11. **Public beta workflow.** After GO, establish a persistent public beta at `beta.phasekit.app`, preserving stable production. Proposed mapping: `main` → existing production project; `beta` → a separate Netlify beta project using the same repository; feature PRs → disposable previews. Promote tested changes through a reviewed beta-to-main release PR with explicit owner release authorisation. A separate beta project makes domain and deployment ownership clear with external DNS. Confirm current account/configuration before setup; add only the beta DNS record and verify TLS, correct commit, update behaviour and production isolation. Beta needs a visible environment/version label. Browser data is origin-specific: existing preview, beta and production do not automatically share saved records; document backup/import for testers. No configuration was changed while recording this proposal.
12. **Roadmap honesty.** The preview package exists, but these usability issues remain open. Do not label the entire roadmap complete. See the remaining scope below.

## Roadmap gaps recorded before implementation

The following was the initial gap list, retained as history. Current status is in [ROADMAP.md](ROADMAP.md) and [BETA-IMPLEMENTATION.md](BETA-IMPLEMENTATION.md):

- Refrigerant data: 50 unknown safety groups; more source-backed conditional properties, aliases and explicit application data.
- Thermodynamic coverage: additional validated P–T/log(p)–h models and full thermodynamic isolines; no invented extrapolation or unsupported substitutions.
- Leak-check assessment: qualified regulatory review and 3–5 user pilots; repair follow-up scheduling is not implemented by the periodic due-date calculator.
- Device quality: physical-device PWA installation/update rehearsal and assistive-technology validation.
- Native distribution: iOS/Android platform projects, builds, devices, signing and store/privacy materials. Capacitor configuration is only preparation.
- Field tools: refrigerant pipe sizing/pressure-loss models, manufacturer-specific substitution sources and richer service-document workflows.
- This new batch adds UI regression repairs, useful converter extensions, pipe expansion and a persistent beta/release workflow. Image export remains a candidate for field testing.
