# Offline saturation calculations

PhaseKit ships a static saturation table generated from CoolProp 7.2.0 HEOS equations of state and predefined mixture models. CoolProp is MIT licensed. The Python wheel used to generate this table reports Git revision `98b3523d5daa98454618d381d2ae53f7471d216b`; its source is [CoolProp v7.2.0](https://github.com/CoolProp/CoolProp/tree/v7.2.0). This is a **model-derived** engineering calculation, not a measured or legally verified property. It is distinct from the separately pinned CoolProp development corpus used for catalogue identity data.

`packages/core/generated/pt-curves.json` contains only the curve points, exact canonical refrigerant IDs and the CoolProp fluid names. Its `dataVersion` includes a SHA-256 prefix of the sorted curve payload, so metadata changes when curve values change. The app needs no Python installation, network request or remote property API at runtime. `data/pt/generate.py` rebuilds it using a CoolProp 7.2.0 Python installation and the pinned identity checkout as its optional positional argument; `data/pt/coverage-manifest.json` lists unsupported IDs and reasons. At the current source versions, **134 of 249** catalogue refrigerants have at least one usable bounded curve: all 134 have both bubble and dew branches after the 2026-09-30 range audit. Some predefined blends are listed by CoolProp but their required binary interaction parameters are unavailable, so CoolProp cannot calculate a trustworthy saturation curve. Six upstream pure-fluid EOS files added after the 7.2.0 wheel are loaded unchanged through its supported JSON model interface. R31 and blends lacking a complete model still return unsupported rather than a substitute curve.

R404A, R407C, R410A and R507A use their exact blend-specific pseudo-pure equations of state (Lemmon 2003), rather than the general `.mix` solver. Their catalogue identity remains a blend and both branches remain separate. No different refrigerant is substituted.

## Pinned model additions

`data/coolprop_runtime.py` loads six unmodified upstream EOS JSONs from CoolProp commit `afce86ff977552663ca3a78d8ea318cc64dcbdfd`: R1123, R1130(E), R1132a, R1132(E), R1224yd(Z) and R1336mzz(Z). The supplement manifest pins every file's SHA-256, CAS, model name and original EOS bibliography. All six generators/validators use this same loader; the existing MIT notice is retained. This extends the model corpus, not the 7.2.0 runtime. The raw EOS files are build inputs and are not shipped in the browser bundle.

R452B, R454C, R455A and R513B use the catalogue's verified UNEP mass recipes. The generator checks each component CAS, converts exact mass fractions with CoolProp's own molar masses, and retains full-precision mole fractions, recipe source IDs and built-in binary-pair policy in the manifest. No interaction parameters, substitute fluids or simple mixing rules are introduced. R448A lacks the R1234ze(E)/R125 pair; R515A/B lack R1234ze(E)/R227ea. These remain unsupported even where an exact recipe is known.

See [the source review](MODEL-EXPANSION-2026-09-30.md) for independent model checks. Catalogue critical/triple-point facts do not override EOS limits. In particular R1132(E)'s physical triple point is distinct from the 240 K model minimum.

The table stores separate bubble (`Q=0`) and dew (`Q=1`) branches. Pressure is **absolute bar** internally. Interpolation is linear in log pressure between temperature nodes; it never extrapolates. Generation starts above the greater of the model minimum and the model-reported triple-point temperature. It ends at least 3 K below a reported critical temperature for ordinary refrigerants; very low critical-temperature gases use a 2% temperature gap. The model maximum temperature is also respected. There is no blanket 180 °C ceiling. For mixtures without a usable critical-point query, successful saturation intervals define a **numerical coverage boundary**, not a physical critical point. The generator examines all continuous intervals, validates serialized endpoints and eighth points, and selects the widest validated temperature span. A failed solver point splits a run; it is never bridged. Independently observed solver failures are retained in `data/pt/solver-failures.json`, pinned to the CoolProp revision, with a ±5 K guard (one full coarse interval on each side). These are conservative numerical exclusions, not freezing/critical limits. The validator checks that no published branch intersects them. `data/pt/coverage-manifest.json` records the model bounds, search policy and actual published branch bounds for every supported refrigerant. Model minima must not be interpreted as actual freezing or triple-point limits. Missing or out-of-range inputs return explicit unsupported/out-of-range errors through the calculation wrapper. Gauge pressure requires an explicit atmospheric reference; PhaseKit never silently assumes standard atmosphere.

The 2026-09-30 generated table passed 68,028 fresh CoolProp evaluations (zero source failures; maximum pressure error 0.1294%, inverse-temperature error 0.03651 °C) at held-out fifth points, distinct from the generator's screening points. `data/pt/validation.json` records the exact data version, check count, maximum pressure and inverse-temperature errors, source failures, and all branch bounds. Acceptance remains **0.3% pressure** and **0.1 °C inverse temperature** within each shipped curve. These checks measure interpolation against the source model, not physical accuracy, equipment suitability or completeness of every refrigerant's phase envelope. The cross-source R410A 56 °C regression uses Chemours' [Freon 410A SI table, page 6](https://www.chemours.com/en/-/media/files/freon/freon-410a-si-thermodynamic-properties.pdf); its different equation of state is checked with a separate 1% tolerance. Regenerate and rerun `data/pt/validate.py` after a model or table change.

Reproduction: `uv run --with CoolProp==7.2.0 python data/pt/generate.py /path/to/pinned/CoolProp` followed by `uv run --with CoolProp==7.2.0 python data/pt/validate.py`. The generator requires identity commit `afce86ff977552663ca3a78d8ea318cc64dcbdfd`. The application never extrapolates beyond these bounds. A P–T range is distinct from the separately validated p–h enthalpy-grid range.

Superheat uses measured vapour temperature minus **dew** temperature at the measured pressure. Subcooling uses **bubble** temperature minus measured liquid temperature. The signed result is in kelvin of temperature difference and the equivalent Fahrenheit temperature difference. Negative results are kept as signed evidence rather than silently clamped. Temperature input accepts Celsius or Fahrenheit.

The kg ↔ tonnes CO₂e tool requires an explicitly selected, verified GWP fact with a named basis and source ID. It multiplies by the selected 100-year GWP for kg → tonnes CO₂e and divides by that same factor for the reverse calculation. It uses decimal arithmetic without threshold rounding; the reverse result is capped at 40 significant digits when division repeats. A verified zero GWP converts any charge to zero tonnes CO₂e, while inverse conversion from zero GWP is undefined. Unknown GWP or missing legal basis blocks the calculation. A GWP from another assessment basis is never substituted automatically.
