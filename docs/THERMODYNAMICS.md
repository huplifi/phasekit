# Offline saturation calculations

PhaseKit ships a static saturation table generated from CoolProp 7.2.0 HEOS equations of state and predefined mixture models. CoolProp is MIT licensed. The Python wheel used to generate this table reports Git revision `98b3523d5daa98454618d381d2ae53f7471d216b`; its source is [CoolProp v7.2.0](https://github.com/CoolProp/CoolProp/tree/v7.2.0). This is a **model-derived** engineering calculation, not a measured or legally verified property. It is distinct from the separately pinned CoolProp development corpus used for catalogue identity data.

`packages/core/generated/pt-curves.json` contains only the curve points, exact canonical refrigerant IDs and the CoolProp fluid names. Its `dataVersion` includes a SHA-256 prefix of the sorted curve payload, so metadata changes when curve values change. The app needs no Python installation, network request or remote property API at runtime. `data/pt/generate.py` rebuilds it using a CoolProp 7.2.0 Python installation and the pinned identity checkout as its optional positional argument; `data/pt/coverage-manifest.json` lists unsupported IDs and reasons. At the current source versions, **124 of 249** catalogue refrigerants have at least one usable bounded curve: 119 have both bubble and dew, three have bubble only, and two have dew only. Some predefined blends are listed by CoolProp but their required binary interaction parameters are unavailable, so CoolProp cannot calculate a trustworthy saturation curve. Some catalogue pure fluids were added to the pinned identity corpus after the 7.2.0 model. Those records return unsupported rather than a substitute curve.

The table stores separate bubble (`Q=0`) and dew (`Q=1`) branches. Pressure is **absolute bar** internally. Interpolation is linear in log pressure between temperature nodes; it never extrapolates. Generation starts above the model minimum temperature and ends at least 3 K below a reported critical temperature for ordinary refrigerants; very low critical-temperature gases use a 2% temperature gap. For predefined mixtures without a usable critical-point query, the generator bounds the last continuous valid interval and leaves a further 5 K gap when a high-temperature solver failure is observed. Missing or out-of-range inputs return explicit unsupported/out-of-range errors through the calculation wrapper. Gauge pressure requires an explicit atmospheric reference; PhaseKit never silently assumes standard atmosphere.

The generated table was checked against **30,564 fresh CoolProp evaluations at held-out quarter points**. Maximum relative pressure error was **0.0961%** and maximum inverse temperature error was **0.0238 °C** over that checked set. Runtime metadata conservatively states **0.3% pressure** and **0.1 °C inverse temperature** limits within each shipped curve. These are interpolation checks against the source model, not bounds on the CoolProp model's agreement with a physical system. `data/pt/validation.json` records the check and extreme cases. Regenerate and rerun `data/pt/validate.py` after a model or table change.

Superheat uses measured vapour temperature minus **dew** temperature at the measured pressure. Subcooling uses **bubble** temperature minus measured liquid temperature. The signed result is in kelvin of temperature difference and the equivalent Fahrenheit temperature difference. Negative results are kept as signed evidence rather than silently clamped. Temperature input accepts Celsius or Fahrenheit.

The kg ↔ tonnes CO₂e tool requires an explicitly selected, verified GWP fact with a named basis and source ID. It multiplies by the selected 100-year GWP for kg → tonnes CO₂e and divides by that same factor for the reverse calculation. It uses decimal arithmetic without threshold rounding; the reverse result is capped at 40 significant digits when division repeats. A verified zero GWP converts any charge to zero tonnes CO₂e, while inverse conversion from zero GWP is undefined. Unknown GWP or missing legal basis blocks the calculation. A GWP from another assessment basis is never substituted automatically.
